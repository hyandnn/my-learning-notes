# SLAM 自学笔记整理规则

适用于 `SLAM/` 与 `docs/slam/` 下由导师对话、课程讲解、阶段总结形成的自学笔记。

## 目标

把课堂实录整理成适合复习、回看和后续沉淀的学习笔记。

整理后的笔记应保留：

- 课程主线
- 核心概念
- 关键直觉
- 推理过程
- 重要问答
- 阶段总结与作业

同时压缩或删除：

- 寒暄、鼓励、重复开场
- 与 SLAM 学习无关的闲聊
- 多次重复但没有新增信息的铺垫
- 过长的戏剧化表达
- 不影响理解的口语停顿

## 整理原则

### 1. 不把课程笔记改成普通百科

SLAM 自学笔记保持课程学习路径，不改写成脱离章节的百科条目。

每章仍应保留“为什么学、怎么想、如何推到下一步”的学习路径。

### 2. 保留压缩版导师风格

如果某段内容用于解释一个重要直觉，即使表达口语化，也应压缩保留。

例如：

- 为什么机器人需要 SLAM
- 为什么状态可以预测
- 为什么 Prediction 和 Observation 要融合
- 为什么 Confidence 会影响权重

### 3. 删除非学习内容

以下内容默认删除：

- “太好了”“哈哈”“从今天开始我们正式上课”等寒暄
- 对学习者的泛泛表扬
- 与本章知识无关的导师评价
- 重复的课程宣言
- 和当前主题无关的跑题内容

例外：如果评价本身指出了学习阶段变化或知识结构变化，可压缩放入“学习反馈”。

### 4. 章节结构统一

每章整理后建议使用：

```markdown
---
title:
course: Robot Perception & SLAM
part:
week:
chapter:
chapter_type: lecture
tags:
status: organized
---

# Week N Chapter M：标题

## 本章目标
## 本章位置
## 核心问题
## 知识地图
## 正文
## 关键直觉
## 易混点
## 本章小结
## 课后任务
## 相关笔记
```

不强行凑空章节；没有内容的章节可以省略。

### 5. 数学型章节结构

涉及概率论、线性代数、微积分、滤波器或公式推导时，在通用章节结构的基础上按需加入：

```markdown
## 前置知识
## 符号表
## 基本假设
## 概念直觉
## 公式定义
## 公式推导
## 推导结果与解释
## 适用条件与方法边界
## 例题
## 易错点
## 思考题
```

这些小节服务于理解，不要求每章机械地全部出现。至少应保证：读者能够识别符号和假设，能够复算核心推导，并能说明结果在机器人学中的意义。

#### 前置知识

只列出理解本章实际需要的知识，并尽量链接本课程内部已有章节。不要把前置知识扩写成另一篇教程。

#### 符号表

首次集中出现多个数学符号时，使用表格说明：

| 符号 | 含义 | 维度 | 单位或取值范围 |
| --- | --- | --- | --- |
| $\mathbf{x}_t$ | 时刻 $t$ 的状态向量 | $n \times 1$ | 由状态定义决定 |
| $\mathbf{P}_t$ | 状态协方差矩阵 | $n \times n$ | 对应状态单位的乘积 |

简单章节可以在公式后就地解释，不必为了形式单独建立符号表。同一符号在一章内必须保持同一含义；若沿用前章记号，应明确说明。

#### 基本假设

推导前应列出会影响结论的假设，例如：

- 系统模型是否线性
- 噪声是否为零均值 Gaussian
- 噪声之间是否独立
- 协方差矩阵是否正定或半正定
- 线性化是否只在当前估计附近成立

假设是计算模型的一部分，不得写成关于真实世界的普遍事实。

### 6. 数学对象与公式规范

每个核心公式附近都应回答四个问题：

1. 公式中的符号分别表示什么，维度和单位是什么？
2. 这个公式解决什么问题？
3. 它在什么假设和条件下成立？
4. 数学结果对应什么机器人学直觉？

根据内容性质明确使用以下标签或措辞，不得混为一谈：

- **定义**：约定一个对象的含义
- **假设**：为建模或推导主动接受的前提
- **恒等式**：在给定定义域内始终成立
- **近似**：只在特定条件或局部范围内成立，使用 $\approx$
- **推导结果**：由前述定义和假设得到
- **经验结论**：来自工程观察，不是数学必然

例如，Gaussian Belief 是一种可计算的分布模型；一阶 Taylor 展开是当前线性化点附近的局部近似。不得将二者描述为真实世界必然满足的性质。

#### LaTeX 与 Obsidian 兼容性

- 行内公式统一使用 `$...$`
- 独立公式统一使用 `$$...$$`
- 矩阵使用 `bmatrix`、`pmatrix` 等标准环境
- 对齐的多行推导使用 `aligned` 或 `align` 兼容写法
- 向量和矩阵的粗体记法在同一章内保持一致
- 公式不得写成 `[ ... ]`，也不得在公式行前添加 `#`
- 不使用 Markdown 标题、代码块或纯文本模拟本应由 LaTeX 表达的公式

推荐写法：

```latex
$$
\begin{aligned}
\mathbf{x}_{t|t-1} &= \mathbf{F}_t\mathbf{x}_{t-1|t-1} + \mathbf{B}_t\mathbf{u}_t \\
\mathbf{P}_{t|t-1} &= \mathbf{F}_t\mathbf{P}_{t-1|t-1}\mathbf{F}_t^\top + \mathbf{Q}_t
\end{aligned}
$$
```

### 7. 公式推导规范

数学型章节采用“尽量完整”的推导标准。核心推导应保留：

1. 推导目标
2. 已知定义和基本假设
3. 推导起点
4. 中间代数步骤
5. 每个关键变形使用的定理、性质或假设
6. 最终结果
7. 结果解释与适用边界

不得为了缩短笔记而省略影响读者独立复算的步骤。可以合并机械重复的代数运算，但必须说明合并了什么，并保证从上一行到下一行仍可验证。

多步推导后应增加两个简短说明：

```markdown
### 推导得到什么

说明最终公式在数学上表达了什么。

### 在 SLAM 中怎么用

说明该结果对应的状态、观测、信息或工程操作。
```

同一公式的重复推导只保留最完整、最清楚的一版。不同角度的解释若能建立重要直觉，可以压缩为“导师提示”，但不得重复整段推导。

### 8. 数学内容的核验与修订

整理数学笔记不仅是排版，也包括基本正确性核验。

- 明确的公式、符号或推导错误应修正
- 修正后在相关位置加入简短注记，说明原记录的问题和修正结果
- 若无法可靠判断，应保留必要上下文并标记 `待核验`
- 不得静默猜测缺失公式，不得把存疑内容改写成确定结论
- 若后文依赖某个待核验结论，应同步标出依赖关系

推荐格式：

```markdown
> [!note] 修订说明
> 原记录此处将观测噪声协方差写为 $\mathbf{Q}$；按本章符号约定修正为 $\mathbf{R}$。
```

```markdown
> [!warning] 待核验
> 此处缺少从第二步到第三步的条件，暂不补写结论。
```

### 9. 问答处理

师生互动中的有效问题应保留，但不保留完整聊天格式。

推荐整理为：

```markdown
## 学习中的问题

### Q1：问题

回答……
```

如果问题推动了课程结构变化，应在时间表中体现。

### 10. 例子与反例处理

同一概念有多个重复例子时：

- 保留最清楚的 1 个主例子
- 其他例子只在必要时一句话带过
- 不删除用于区分概念边界的反例

数学例题应保留：

1. 已知条件和输入
2. 使用的公式及选择理由
3. 完整计算过程
4. 计算结果
5. 结果的物理或概率意义

优先保留能够说明假设失效、近似误差或方法边界的反例。例题中的符号应与正文保持一致；若为了简化改用一维或低维例子，应明确说明简化了什么。

### 11. 思考题与参考答案

章末思考题保留在正文中，用于复习和自测。参考答案紧随题目，使用 Obsidian 可折叠 callout：

```markdown
### 思考题 1

问题……

> [!answer]- 参考答案
> 答案……
```

参考答案应解释推理过程，不只给最终结论。若存在多个合理答案，应说明各自成立的条件。

### 12. 图示与数学图形

Mermaid 只用于表达：

- 知识结构
- 数据流和信息流
- 算法步骤
- 模块关系
- 学习顺序

函数曲线、概率密度、几何关系和误差椭圆等数学图形，不用 Mermaid 流程图代替。没有合适图片时，可保留简洁、对齐良好的文本示意，并明确其仅用于直觉说明；后续也可以替换为独立图片。

图示不能代替公式定义或推导。数学图形必须配有坐标、变量或必要说明，避免只追求视觉效果。

### 13. 时间表更新原则

`Timetable.md` 不以最初计划为准，而以实际学习内容为准。

更新时应记录：

- 实际完成了哪些 Chapter
- 每章真实主题
- 是否新增了原计划外章节，如 Chapter 5.5
- 哪些内容提前、延后、拆分或合并
- 下一阶段建议学习顺序

### 14. 概念标记留在课程笔记内

整理课程笔记时，不把某一章拆出去另写成独立百科页。

如果某章已经形成稳定概念，可在文内标记：

```markdown
可沉淀为 Concept：State / Belief / Prediction / Observation
```

后续若要单独成文，仍放在本学习库内。

## 数学型章节检查清单

整理完成后逐项检查：

- [ ] 核心符号均已定义，且全文含义一致
- [ ] 向量、矩阵的维度能够相乘或相加
- [ ] 单位或取值范围在需要时已注明
- [ ] 行内公式和块级公式均使用 Obsidian 兼容 LaTeX
- [ ] 不存在被误解析为 Markdown 标题的公式
- [ ] 核心推导包含起点、关键中间步骤和结论
- [ ] 每个关键变形能够追溯到定义、定理、性质或假设
- [ ] 定义、假设、恒等式、近似、推导结果和经验结论已区分
- [ ] 每个核心结论都说明了适用条件和方法边界
- [ ] 多步推导后说明了“推导得到什么”和“在 SLAM 中怎么用”
- [ ] 修正内容有修订说明，无法确认的内容标记为 `待核验`
- [ ] 例题包含输入、过程、结果和解释
- [ ] 思考题答案使用可折叠 callout
- [ ] Mermaid 没有被用来冒充函数曲线或概率分布图
- [ ] 结论没有从局部近似、特定模型或单个例子过度外推

## 禁止

- 删除技术事实、定义、公式、关键例子
- 把不确定的课堂推导改成确定结论
- 为了变短而删掉推理链
- 省略影响复算的关键推导步骤
- 不说明假设、维度或适用条件就孤立地堆放公式
- 把近似、模型假设或经验规律写成普遍真理
- 静默修正、猜测或补全存疑的数学内容
- 使用错误的 Markdown 语法模拟 LaTeX 公式
- 把学习笔记改成纯条目百科
- 擅自移动目录或重命名文件


## 公开发布补充

网站正文、章节迁移和公开导航遵循 [Publishing](../../.regulation/Publishing.md)。网站问答使用标准 `<details>` 折叠块，公开正文使用标准 Markdown 链接；学习草稿仍可使用 Obsidian callout。
